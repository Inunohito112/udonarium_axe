## 2. v0.2でGM・PL権限を固める

本家の役割は `gm`、`pl`、`guest` の三つである。現在のUIでは、GMだけが変更できる共有設定、PLも変更できるテーブル設定と戦闘ルール、見学者には編集させない操作に分かれている。

受信側には別の問題がある。`UPDATE_GAME_OBJECT` と `DELETE_GAME_OBJECT` は、送信者の役割や所有者を検査せず適用される。役割を表す `PeerCursor` 自体も同期オブジェクトなので、UIを隠すだけでは権限にならない。

### 2.1 先に権限表を固定する

- [ ] 操作対象を「部屋」「テーブル」「キャラクター」「カード」「進行」「演出」に分ける
- [ ] GM、PL、見学者ごとの閲覧・作成・更新・削除を決める
- [ ] PL所有物、GM所有物、所有者なしを分ける
- [ ] GM不在時の扱いを決める
- [ ] GM交代と再接続時の扱いを決める
- [ ] 拒否した操作を画面とログのどちらへ出すか決める

### 2.2 同期の入口を守る

- [ ] 実際の接続元peer IDとメッセージ内の送信者を結びつける
- [ ] オブジェクト種別ごとの変更許可を判定する純関数を作る
- [ ] 新規作成、更新、削除を別々に判定する
- [ ] GMだけが変更できるオブジェクトを定義する
- [ ] PLは自分が所有するキャラクターとリソースだけ変更できるようにする
- [ ] 見学者から届いた状態変更をすべて拒否する
- [ ] 役割と所有者の変更をGMだけに限定する
- [ ] 拒否した同期データでローカル状態が変化しないことをテストする
- [ ] 正常なPL操作が他端末へ届くことを二者テストする

### 2.3 UIを同じ権限表へ合わせる

- [ ] PLからテーブル設定を開けなくする
- [ ] PLから部屋の共有設定を変更できなくする
- [x] PLから他人とGMのキャラクターシートを編集できなくする
- [ ] PLからラウンドとターンを進められなくする
- [ ] 見学者の編集ボタンとドラッグ操作を無効にする
- [ ] GMは全対象を操作できるようにする

受信拒否とUI制御が同じ判定を読む状態を完了条件にする。別々の条件式を増やすと、どちらか一方だけが更新される。

キャラクターのUI制御では、PLは自分が所有するコマだけを操作でき、他人・GM・所有者なしのコマは詳細表示だけにした。コマ移動、回転、シート、チャットパレット、リモートコントローラー、ホットバー、インベントリの各導線が同じ判定を読む。これはクライアント上の操作制限であり、改造クライアントから届く同期データの受信拒否は2.2の未完了項目として残る。

- [ ] APを数値リソースとスライダーで作る
- [ ] 部位APを数値リソースで作る

- [ ] 四武器をグループとして作る
- [ ] 各武器の弾数を数値リソースとスライダーで作る
- [ ] ENダイス、手番ダイス、ターンダイスをキャラクター所持ダイスで作る

この試作で足りない操作だけを、AC専用画面の要件にする。

ボス行動は、いきなり自動実行しない。対象選択、移動先、使用武器を候補として表示し、GMの確定後に既存の操作を呼ぶところから始める。判断を一段ずつ観測できるため、ルール修正と不具合調査を切り分けやすい。

## 本家更新の取り込み手順

```sh
git fetch upstream --tags
git switch main
git merge --ff-only upstream/main
git push origin main
git switch ac6trpg/v0.1-foundation
git rebase main
```

mainにはAC6TRPG独自変更を直接置かない。各段階を短いブランチとPull Requestにし、ビルド、lint、テストが通った状態で取り込む。
